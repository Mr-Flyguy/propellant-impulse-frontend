# Propellant Impulse Explorer

Клиентское веб-приложение (Single Page Application) на React 19, TypeScript, Redux Toolkit и Vite для интерактивной визуализации физических характеристик рабочих тел ядерных ракетных двигателей, фильтрации каталога, авторизации специалистов и управления публикацией компонентов.

---

## 1. Архитектура управления состоянием (Redux Toolkit)

Глобальное состояние приложения управляется централизованным хранилищем Redux Toolkit (`src/store/index.ts`) и разделено на три предметных среза (slices):

1. **`authSlice` (`src/store/slices/authSlice.ts`)**:
   - Управление состоянием аутентификации инженера (`user`, `isAuthenticated`, `loading`, `error`).
   - Переключение интерфейса между гостевым режимом и авторизованным профилем.
   - Запросы входа, регистрации и выхода выполняются напрямую через Axios с ручной передачей состояния в Redux без кодогенерации и thunk.
   - Сессионный идентификатор сохраняется браузером в HTTP-only Cookie (`sessionId`).

2. **`filterSlice` (`src/store/slices/filterSlice.ts`)**:
   - Хранение параметров фильтрации каталога: максимальная молярная масса (`maxMolarMass`) и поисковый запрос по наименованию (`searchQuery`).
   - Автоматический сброс значений фильтра к исходным настройкам при выходе пользователя из системы (`resetFilter`).

3. **`propellantsSlice` (`src/store/slices/propellantsSlice.ts`)**:
   - Асинхронные Thunk-действия на базе сгенерированного API-клиента:
     - `fetchPropellantsThunk` — получение каталога с сервера (с фильтром);
     - `fetchPropellantFeedThunk` — навигация по карточкам ленты;
     - `fetchPropellantDraftThunk` — загрузка черновика текущего пользователя;
     - `createPropellantDraftThunk` — создание черновика с прикреплением файлов в MinIO;
     - `publishPropellantThunk` — публикация черновика в общий каталог;
     - `deletePropellantThunk` — мягкое удаление рабочего тела создателем (`is_creator === 1`);
     - `toggleLikePropellantThunk` — выставление и снятие отметки «нравится».
   - **Автономный режим (Mock Fallback)**: при отсутствии соединения с бэкендом методы автоматически переключаются на локальную коллекцию mock-объектов.
   - **Блокирующая анимация**: флаг `loading` активирует оверлей, блокирующий элементы управления на время AJAX-запроса.

## 2. Кодогенерация API-клиента из Swagger

Взаимодействие с бэкендом строится на основе OpenAPI/Swagger спецификации:
- Спецификация выгружается из бэкенд-сервиса в файл `swagger.json`.
- Кодогенерация типизированного клиента Axios выполняется командой:
  ```bash
  npm run generate:api
  ```
- Сгенерированный код расположен в `src/api/generated/PropellantApi.ts` и содержит полные TypeScript-интерфейсы DTO и типизированные методы.

---

## 3. Обратный прокси (Vite Reverse Proxy)

Для исключения проблем с CORS и прозрачной маршрутизации запросов настроен обратный прокси в `vite.config.ts`:
- `/api/*` — перенаправляется на бэкенд NestJS (`http://localhost:3000`);
- `/propellants/*` — перенаправляется на объектное хранилище MinIO (`http://localhost:9000`) для прямой загрузки медиафайлов без CORS.

## 4. Экраны приложения

1. **«Лента» (`#/feed`, `#/feed/:id`)**:
   - Полноэкранный плеер видеозаписи струи истечения и параметров рабочего тела;
   - Кнопка отметки «нравится» (для авторизованных специалистов);
   - Кнопка «Далее >» для циклического просмотра компонентов;
   - Раскрывающееся инженерное описание вещества.

2. **«Добавление» (`#/create`)**:
   - Двухшаговый мастер создания компонента:
     - Шаг 1: ввод наименования, загрузка схемы и видеофайла истечения струи в хранилище;
     - Шаг 2: ввод молярной массы, показателя адиабаты и описания с последующей публикацией;
   - Для неавторизованных гостей отображается приглашение выполнить вход.

3. **«Плитка» (`#/catalog`)**:
   - Двухколоночный каталог опубликованных рабочих тел;
   - Ползунок и текстовое поле фильтрации по молярной массе и строке поиска;
   - Кнопка «Подробнее» с раскрытием описания;
   - Кнопка удаления на карточке (отображается только для автора записи `is_creator === 1`).

4. **«Вход / Выход» (`#/login`)**:
   - Гостевой режим: формы входа и регистрации учетной записи;
   - Авторизованный режим: карточка инженера (логин, почта, роль, статус сессии) и кнопка «Выйти из системы» со сбросом фильтров.

---

## 5. Быстрый запуск

```bash
# 1. Установка зависимостей
npm install

# 2. Запуск в режиме разработки
npm run dev

# 3. Сборка production-бандла
npm run build
```
