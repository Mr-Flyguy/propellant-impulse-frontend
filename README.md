# Propellant Impulse Explorer

Клиентское веб-приложение (Single Page Application) для интерактивной визуализации физических характеристик рабочих тел ядерных ракетных двигателей (ЯРД) и воспроизведения динамики истечения реактивной струи.

Проект разработан на базе современного стека React 19, TypeScript и Vite, сфокусирован на компонентной архитектуре, строгой типизации, клиентоориентированной маршрутизации и отказоустойчивой обработке медиапотоков.

---

## Ключевые возможности

- **Каталог рабочих тел**: двухколоночное плиточное отображение карточек веществ с физическими параметрами (молярная масса $M$, показатель адиабаты $\gamma$, оценка инженерного сообщества).
- **Интерактивная фильтрация**: плавное регулирование верхнего предела молярной массы в диапазоне 1.00–64.00 г/моль с реактивным обновлением сетки компонентов в реальном времени.
- **Полноэкранная медиа-лента**: зацикленное видеовоспроизведение динамики истечения реактивной струи в высоком качестве, индикация телеметрии и раскрывающееся инженерное описание.
- **Отказоустойчивая подсистема медиа (Fallback)**: автоматическая обработка сетевых сбоев и ошибок декодирования с переключением на локальные резервные графические и видеоресурсы.
- **Клиентская маршрутизация (Hash Routing)**: навигация на основе URL-хэша (`#/catalog`, `#/feed/:id`), поддержка истории браузера («Назад» / «Вперед») и сохранение контекста при обновлении страницы (`F5`).
- **Автономный mock-слой**: асинхронное получение данных через стандартный протокол HTTP `fetch` с резервной статической коллекцией.

## Архитектура и организация кода

Приложение построено по принципам функционального программирования и компонентно-ориентированной архитектуры React без использования тяжеловесных внешних хранилищ (Redux, MobX) и без Context API.

### Иерархия компонентов и организация потока данных

Приложение использует однонаправленный поток данных (Unidirectional Data Flow):

- **Корневой компонент (`App.tsx`)**:
  - Управляет центральным состоянием приложения: активной вкладкой (`activeTab`), индексом текущего видео в ленте (`feedIndex`), порогом молярной массы (`filter`) и списком рабочих тел (`data`).
  - Обеспечивает клиентскую маршрутизацию по URL-хэшу (`window.location.hash`), отслеживая события `hashchange` и `popstate`.
  - Выполняет реактивную фильтрацию коллекции с помощью `useMemo` и передает отфильтрованный набор и функции обратного вызова дочерним компонентам.
- **Страница каталога (`CatalogPage.tsx`)**:
  - Принимает отфильтрованный список рабочих тел и текущее пороговое значение через `props`.
  - Предоставляет элементы управления фильтрацией (ползунок с диапазоном 1.00–64.00 г/моль) и двухколоночную сетку карточек.
  - Обрабатывает ошибки загрузки превью с переключением на резервное изображение и передает событие клика по карточке в корневой компонент для перехода в ленту.
- **Страница медиа-ленты (`FeedPage.tsx`)**:
  - Отображает выбранное рабочее тело в полноэкранном режиме с зацикленным видеорядом истечения реактивной струи.
  - Выводит информационные бейджи телеметрии (молярная масса, показатель адиабаты, число отметок) и раскрывающееся инженерное описание.
  - Реализует перехват ошибок воспроизведения видеопотока с автоматической подстановкой локального ролика `/video/default_exhaust.mp4`.
- **Нижняя панель навигации (`NavbarBottom.tsx`)**:
  - Отображает четыре функциональные вкладки приложения с визуальным выделением активного экрана.
  - Передает события клика по вкладкам в `App.tsx` для смены текущего представления.

### Принципы реализации:
1. **Подъем состояния (State Lifting)**:
   - Все изменяемые данные приложения (текущий экран, фильтры, индекс просматриваемого объекта, коллекция) хранятся в корневом компоненте `App`.
   - Дочерние компоненты являются чистыми презентационными модулями: они получают данные через свойства (`props`) и инициируют изменения через типизированные функции обратного вызова (Callbacks).
2. **Мемоизация вычислений (`useMemo`)**:
   - Операция фильтрации массива компонентов выполняется только при изменении исходной коллекции или значения порогового фильтра. Это исключает паразитные повторные вычисления при навигации и перерисовках несвязанных элементов.
3. **Безопасная работа с эффектами (`useEffect`)**:
   - Сетевые вызовы изолированы в хуке `useEffect` с контролем статуса монтирования (`isMounted = false` в cleanup-функции), что предотвращает утечки памяти при быстром переключении экранов.

## Спецификация интерфейса и маршрутов

### Карта клиентских маршрутов

| Маршрут | Компонент | Назначение |
| :--- | :--- | :--- |
| `#/catalog` | `CatalogPage` | Реестр рабочих тел: ползунок молярной массы (1.00–64.00), кнопка «Фильтр», двухколоночная сетка карточек |
| `#/feed` | `FeedPage` | Полноэкранный плеер ленты: отображение первого рабочего тела из списка |
| `#/feed/:id` | `FeedPage` | Полноэкранный плеер ленты: отображение конкретного рабочего тела с идентификатором `:id` |

### Состав компонентов интерфейса:

#### 1. Мобильный контейнер (`.mobile-app-frame`)
Центрированный контейнер с фиксированными габаритами 390×844px, темной цветовой палитрой и скруглением 36px, оптимизированный под пропорции современных мобильных экранов.

#### 2. Экран каталога (`CatalogPage`)
- **Контроллер молярной массы**: управляемый элемент `<input type="range" min="1.00" max="64.00" step="0.01">` с числовым индикатором текущего значения.
- **Кнопка применения фильтра**: `<button type="submit">` в форме с перехватом события отправки.
- **Сетка карточек**: карточки с оптимизированными превью, параметрами $M$ (молярная масса), $\gamma$ (показатель адиабаты), числом инженерных отметок и кликабельной областью перехода в медиа-ленту.

#### 3. Экран медиа-ленты (`FeedPage`)
- **Видеоконтейнер**: тег `<video>` в режиме `autoPlay loop muted playsInline` с перехватом ошибки `onError` и автоматической активацией локального ролика `/video/default_exhaust.mp4`.
- **Блок телеметрии**: информационные капсулы параметров $M$ и $\gamma$, значок атома и счетчик одобрений.
- **Элементы управления**:
  - Кнопка **«Далее >»**: циклический переход к следующему объекту в наборе;
  - Спойлер описания `<details>` / `<summary>`: переключение подробного инженерного описания.

#### 4. Фиксированная навигационная панель (`NavbarBottom`)
Нижняя панель с матовым размытием фона (`backdrop-filter: blur(16px)`), содержащая 4 функциональные вкладки:
- **ЛЕНТА**: доступна, активный индикатор перехода в видеоплеер;
- **ДОБАВИТЬ**: заблокирована (`disabled`);
- **ПЛИТКА**: доступна, активный индикатор перехода в каталог;
- **ВХОД**: заблокирована (`disabled`).

## Инструкция по сборке и развертыванию

### Системные требования
- **Node.js**: версия `20.18+` (или `22.x LTS`)
- **Пакетный менеджер**: `npm` версии `10+`

### 1. Установка зависимостей
```bash
npm install
```

### 2. Запуск сервера для разработки (Dev Server)
```bash
npm run dev
```
Сервер разработки запустится на локальном порту (по умолчанию: `http://localhost:5173/`). При открытии в браузере активируется автоматический роутинг на каталог `#/catalog`.

### 3. Проверка типов и производственная сборка
```bash
npm run build
```
Команда инициирует проверку типов TypeScript (`tsc -b`), после чего Vite формирует оптимизированный production-бандл в директории `dist/` (минификация CSS/JS, tree-shaking, хеширование ассетов).

### 4. Локальный предпросмотр production-сборки
```bash
npm run preview
```
Запускает легковесный веб-сервер для проверки собранного бандла из каталога `dist/`.
